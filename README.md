# sudrfpractice

Правовая база судебных актов кассационных судов общей юрисдикции: харвестер
собирает с сайтов девяти КСОЮ и Кассационного военного суда сплошные перечни
дел и тексты актов, база даёт по ним поиск — полнотекстовый, по реквизитам,
по цитируемым нормам и семантический.

Приложение [`Sudrf`](https://github.com/arvidsever/Sudrf) остаётся интерактивным
инструментом юриста и позже может стать клиентом этого API. Сбор в него
не встраивается.

## Состояние

**Перечень собирается.** Первый боевой обход прошёл 19.08.2026: 2 КСОЮ,
гражданская кассация, окно по дате публикации 01–07.06.2026 — **530 дел
из 530 обещанных счётчиком**, 22 страницы, 1 мин 5 с, дроссель 3 с на хост.

Тексты актов ещё не собираются. Следующий шаг — карточки дел.

**Перечень требует длинного `delo_id`.** С короткой парой из реестра
(`delo_id=5`, `delo_id=4`) портал отдаёт тот же счётчик и те же дела,
но озаглавливает выдачу «апелляция» и не даёт ссылок на тексты актов.
Счётчик при этом сходится — ошибка молчит.
Разбор и детектор — [`docs/delo-id-and-act-links.md`](docs/delo-id-and-act-links.md).

## Что лежит в репозитории, а что нет

Код, справочники, фикстуры и **замер объёма корпуса**
([`data/corpus-volume.json`](data/corpus-volume.json)) — здесь.

Вне git намеренно:

| | Почему |
| --- | --- |
| `raw/` — сырые страницы | десятки гигабайт; и те же персональные данные, что в базе |
| `data/captcha-training/` — корпус капч | 67 МБ, 17 тыс. файлов |
| `data/captcha-model.json` — веса решателя | рабочий решатель капчи госпортала в открытом доступе — это не то, что стоит публиковать |
| содержимое базы — дела и тексты | строка выдачи уголовной кассации и КоАП несёт ФИО вместе со статьёй (`docs/ethics.md`) |

Репозиторий публичный, и это осознанное разделение: код и метод —
открыты, собранные данные и средства доступа — нет.

## Откуда знание

Механика перечня описана в **[`Docs/architecture/ksoyu-listing-grammar.md`](https://github.com/arvidsever/Sudrf/blob/main/Docs/architecture/ksoyu-listing-grammar.md)**
репозитория `Sudrf` — грамматика проверена живьём 06.08.2026 на всех десяти
кассационных судах. Здесь она не дублируется: один источник истины, ссылки
из кода ведут туда.

Оттуда же приезжают справочники судов и картотек:

```bash
swift run sudrf-cli export-directories --what courts    > data/directories/courts.json
swift run sudrf-cli export-directories --what cartoteki > data/directories/cartoteki.json
```

## Устройство

```
src/harvester/
  config.py       правила доступа: два дросселя, UA, окно обхода, потолок запросов
  directories.py  справочники судов и картотек + то, что знает только харвестер
  encoding.py     windows-1251 — сквозное требование платформы
  urls.py         сборка URL перечня, акта, карточки
  http.py         клиент с дросселем на хост и журналом
  raw.py          слой сырых HTML — источник истины
  guards.py       классификация ответа: выдача / нет данных / капча / неизвестно
  parse/          разбор перечня и текста акта
  harvest.py      обход окна: страницы, сверка со счётчиком, журнал
  cards.py        обход карточек: тексты, участники, статьи, движение
  db/             схема и наполнение справочников
migrations/       alembic
tests/fixtures/   шесть живых страниц
```

Три вещи, ради которых всё это выглядит именно так:

**Строка выдачи самодостаточна.** Номер, дата поступления, категория, судья,
дата решения и результат берутся без открытия карточки, а в последней колонке
лежит прямая ссылка на текст акта. Текст по ней совпадает символ в символ
с блоком карточки — значит **на дело хватает одного запроса вместо двух**.

**Тихий отказ — главный риск.** Платформа отвечает `200 OK` на любой кривой
запрос, и он неотличим от честной пустоты. Выдачей считается только ответ
с `table#tablcont`, число строк сверяется со счётчиком, окна обхода пишутся
в `harvest_run`. Иначе корпус недосчитается молча.

**Сырьё хранится до разбора.** Парсеры заведомо будут дорабатываться;
архив `raw/` избавляет от повторного обхода судов при каждой доработке.

## Запуск

```bash
brew install postgresql@18 pgvector uv
brew services start postgresql@18
createdb praktika
uv venv --python 3.12 && uv pip install -e '.[dev]'
alembic upgrade head
python -m harvester load-directories
```

Локально стоит Postgres 18; целевая версия для VPS — 16, и схема
не использует ничего, чего в ней нет. CI гоняет миграции на 16.

```bash
python -m harvester courts        # справочник судов, с отметкой капчи
python -m harvester cartoteki     # картотеки с парами delo_id/new
python -m harvester url --court 2kas.sudrf.ru --cartoteka g3 \
    --axis publication --from 01.06.2026 --to 07.06.2026
pytest && ruff check
```

Полный индекс по очереди заданий:

```bash
python -m harvester measure     # объём каждой пары суд × картотека
python -m harvester plan        # нарезать глубину на месячные окна
python -m harvester run         # обойти очередь, суды параллельно
python -m harvester queue       # что осталось
```

Прогон рассчитан на то, что его прервут: незакрытые окна возвращаются
в очередь при следующем запуске, а суд, попросивший отступить, ставится
на паузу и пропускается.

Обход одного окна и сбор текстов:

```bash
python -m harvester harvest --court 5kas.sudrf.ru --cartoteka g3 \
    --axis publication --from 01.06.2026 --to 07.06.2026
python -m harvester cards --court 5kas.sudrf.ru
```

Тексты берутся из карточки дела, а не со страницы акта. Стоят они одинаково —
один запрос, — но карточка отдаёт сверх текста участников с ИНН и ОГРН, суд
первой инстанции, движение по событиям и путь жалобы. У уголовных и КоАП там
же лежит перечень вменяемых статей.

Полнота свода текстов измеряется базой, а не памятью о прогоне: берутся
только те акты, у которых ещё нет `act_text`. Прерванный сбор продолжается
сам, повторный запуск ничего не перекачивает.

Без флагов обход идёт только в ночном окне. `--pilot N` снимает это
требование и ограничивает обход N страницами — для наблюдаемого прогона,
когда вы смотрите на вывод.

Тесты идут на отдельной базе `praktika_test` — она создаётся сама.
