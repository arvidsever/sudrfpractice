# Корпус капч ГАС

## Что это

Размеченные капчи с портала ГАС «Правосудие»: PNG 100×30, пять цифр.
**Метка — префикс имени файла**: `74628_oblsud--mo.sudrf.ru_20260711-082351_80D112A5.png`
означает код `74628`. Это ground truth в буквальном смысле — в корпус попадали
только те ответы, которые **портал принял**.

Капча стоит на форме поиска у четырёх кассационных судов из десяти —
1, 3, 4 и 6 КСОЮ (§6 грамматики перечня). Пилот идёт на 2 КСОЮ, где её нет,
поэтому сбор корпуса опережает потребность в модели, а не догоняет её.

## Где корпус лежит и почему не там

Каноническое место — `data/captcha-training/solved/` в этом репозитории,
под `.gitignore`: 67 МБ и 17 тыс. файлов в git не место.

**Каталог приложения `~/Library/Application Support/Sudrf/captcha-training/`
используется только на чтение.** В его `manifest.json` стоит
`numericCeiling: 5000` при `fifoPolicy: oldestFirst` — приложение вправе
подрезать корпус до потолка, и складывать туда 17 тыс. файлов означало бы
однажды недосчитаться двух третей.

нужен, придётся искать не в объёме, а в архитектуре или аугментации.

## Порт на NumPy сверен с оригиналом

Два уровня сверки, оба зелёные:

* **препроцессинг** — расхождение РОВНО НОЛЬ на 60 картинках (все 1 280
  значений каждой). Иначе и быть не может: вход считается усреднением
  целочисленной маски по целочисленной сетке;
* **вероятности** — максимум 3·10⁻⁷ с TTA на 200 картинках, ноль
  расхождений в цифрах. Побитового совпадения тут не бывает: NumPy
  суммирует свёртку в другом порядке, чем последовательный цикл на JS.

Эталон препроцессинга лежит в `tests/fixtures/captcha_reference.json`
и от переобучения не устаревает — сеть в нём не участвует. Эталон
вероятностей снимается на месте: `scripts/dump-captcha-probs.mjs`.

## Как получить модель заново

Решение принято, порядок такой.

### Шаг 1. Прогнать тренер автора `sudtudtestbot`

```bash
brew install node
CAPTCHA_TRAINING_DIR=<repo>/data/captcha-training \
CAPTCHA_MODEL=<repo>/data/captcha-model.json \
node scripts/train-captcha-cnn.mjs
```

Скрипт не тянет ни одной npm-зависимости (только `node:fs`/`path`/`zlib`),
а архитектуру и прямой проход импортирует из того же `server/captcha.js`,
что и инференс, — расхождение train/infer исключено по построению:

```
CNN = { IW: 64, IH: 20, C1: 8, C2: 16, K: 3, PAD: 1, HID: 64, HEADS: 5, NC: 10, LK: 0.1 }
conv8(3×3) → leakyReLU → pool2 → conv16(3×3) → leakyReLU → pool2 → dense64 → leakyReLU
→ 5 голов softmax(10)
```

Вход — карта «чернильности» 64×20: `isDigitPixel` (teal-фильтр) → `inkMap`
→ `poolInk`. Препроцессинг несёт большую часть точности, поэтому повторять
его на глаз нельзя — только сверяясь с эталоном.

На выходе `captcha-model.json` и напечатанные held-out по цифрам, «капча
целиком» с TTA и таблица порогов.

### Шаг 2. Инференс на NumPy

Пять слоёв читаются из JSON напрямую — ONNX не нужен. Порт обязан совпасть
с JS-форвардом на held-out: сверка побитовая, а не «примерно та же точность».

### Шаг 3 (позже). Обучение в PyTorch

Порт обучения, который обязан повторить эталон из шага 1. До тех пор шаг 1
остаётся источником весов.

## Поведение портала, которое нельзя потерять

Из практики `sudtudtestbot` (§6 грамматики; живьём в разведке не перепроверялось):

* одна капча держится на IP по несколько минут и **не меняется от неверных
  ответов** — перебор бесполезен, а вот следы оставляет;
* решённая пара `captcha`+`captchaid` действует **на весь регион** около 6 часов;
* у антибрутфорс-судов (известен Краснодарский краевой) авто-сабмит копит
  блокировку «Информация временно недоступна» на IP — для них только подсказка
  человеку, автоматической отправки быть не должно;
* картинка приходит инлайном как `data:image/png;base64,…` — отдельный запрос
  за ней не нужен;
* карточка дела (`name_op=case`) капчей не защищена ни на одном суде.

Открытый вопрос для боевой проверки: сколько страниц перечня проходит на одной
решённой паре. Ответ задаёт бюджет запросов при раскатке на 1/3/4/6 КСОЮ.
