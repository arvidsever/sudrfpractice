# Суды субъектов: областные, краевые, верховные суды республик

Разведка 16.10.2026, тот же клиент с дросселем и замком, около 50 запросов
на трёх судах и затем счётчики по всем. Страницы сохранены вне репозитория:
в них персональные данные.

## Суды и картотеки

`subjectCourts`): 89 судов, из них 87 на `sudrf.ru`. Не берутся Московский
городской суд (`mos-gorsud.ru` — своя система) и Нижегородский областной
(`nnoblsud.ru` — свой домен). Список — `data/directories/courts-subject.json`.

## Главный риск — снят

У КСОЮ короткая пара `delo_id` отдавала тот же счётчик без ссылок на акты,
и недосбор молчал. У судов субъектов пары из реестра родные: по оси
публикации за 2025–2026 ссылка на акт есть у каждой строки первой страницы
во всех восьми картотеках трёх судов (Калининградский областной,
Красноярский краевой, Верховный суд Татарстана). Выдача разбирается
существующим разбором без правок.

## Включение

Суды субъектов в справочнике есть — по ним ищется суд, строятся адреса,
— но план, добег, прогон очереди, свод карточек и замер их не обходят,
пока уровень `subject` не добавлен в `harvest_levels`:

```
HARVESTER_HARVEST_LEVELS='["cassation","appeal","subject"]'
```

Причина — диск: на собранный акт в базе приходится около 26 КБ (текст
с полнотекстовым индексом, дело, нормы, участники), и полтора миллиона
актов — это ещё 35–50 ГБ при 23 ГБ свободных.

## Индекс за 2025–2026, запущен 16.10.2026

Только перечни, без карточек и текстов: номера, судьи, результаты, ссылки
на акты. Под карточки нужен диск (см. выше).

* План: `plan --from 01.01.2025 --axis publication` по 87 судам — 15 312
  месячных окон. Вставка в очередь частями: одним запросом 15 тысяч окон
  упираются в потолок PostgreSQL в 65 535 параметров.
* Прогон очереди обходит не больше восьми судов одновременно. Первый запуск
  открыл 87 потоков, исчерпал 30 подключений к базе и за минуту завалил
  5 700 окон; их вернули в очередь.
* Включение уровня — только у этого прогона, переменной окружения
  `HARVESTER_HARVEST_LEVELS` в разовом задании systemd. Постоянные задания
  (добег, свод карточек) суды субъектов по-прежнему не трогают.
* Прогон уступает добегу: идёт до 04:30, в 07:45 перезапускается
  транзиентным таймером `sudrf-oblsud-index-day` (20,5 ч). Таймер живёт
  до перезагрузки; когда очередь опустеет, его надо снять:
  `systemctl stop sudrf-oblsud-index-day.timer`.
