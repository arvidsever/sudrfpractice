# Что где лежит

Репозиторий публичный. Разделение проведено осознанно: **код и метод
открыты, собранные данные и средства доступа — нет**.

| Что | Где | Почему так |
| --- | --- | --- |
| Код, справочники, фикстуры | git | это и есть метод |
| Замер объёма корпуса | git, `data/corpus-volume.json` | 2,4 КБ факта |
| Сырые страницы | S3, префикс `raw/` | десятки гигабайт; и персональные данные |
| Веса решателя капчи | S3, префикс `model/` | рабочий решатель капчи госпортала не стоит публиковать |
| Дампы базы | S3, префикс `dump/` | ФИО в строках уголовной кассации и КоАП |

Дамп снимается тем же шестичасовым заданием, но выходит раз в сутки:
команда сама проверяет, есть ли сегодняшний в бакете. Держится семь штук —
по счёту, а не по возрасту: правило «удалять старше недели» после недельного
простоя оставило бы ноль копий ровно тогда, когда они нужны.

Размер: база в 716 МБ даёт дамп в 64 МБ, сжатие в одиннадцать раз.
На полную глубину без векторов это около 3–4 ГБ на копию, то есть
семь копий — 25 ГБ. Вместе с 63 ГБ сырья это близко к базовым 100 ГБ
тарифа, и к тому времени число копий стоит пересмотреть. Векторы
в дамп попадут плохо — они не сжимаются, — а считаются три недели;
как их беречь, решается отдельно.
| Корпус капч | S3 либо только локально | 67 МБ, 17 тыс. файлов |

## Выгрузка идёт сама

`launchd`-задание `ru.sudrfpractice.archive` запускает
[`scripts/archive-run.sh`](../scripts/archive-run.sh) раз в шесть часов,
логи — `logs/archive-YYYY-MM-DD.log`.

Отдельным заданием, а не хвостом ночного прогона: прогон живёт сутками
и завершается редко, а сырьё копится непрерывно — за сутки сбора это
гигабайт с лишним. Ждать конца прогона значило бы всё это время держать
единственную копию на одном диске.

Частые запуски безопасны: второй экземпляр launchd не поднимет, пока идёт
первый, а выгрузка идёт разницей.

## Выгрузка вручную

Хранилище — FirstVDS, услуга открыта 20.08.2026. Адрес и регион уже
прописаны умолчаниями в `config.py`, задать нужно только бакет и ключи:

```bash
# в .env в корне репозитория — он в .gitignore
HARVESTER_S3_BUCKET=sudrfpractice
HARVESTER_S3_ACCESS_KEY=…
HARVESTER_S3_SECRET_KEY=…
```

**Тариф важен для планирования.** 190 ₽ в месяц включают 100 ГБ, сверх
того 1,9 ₽ за гигабайт. Сырьё на полную глубину — около 63 ГБ (16 ГБ
перечней по 74 КБ и 47 ГБ карточек по 17 КБ), то есть в базовый объём
укладывается. Дампы базы и корпус капч добавляются сверху, и вот они
могут вывести за 100 ГБ.

**При неоплате услуга останавливается, а через семь дней данные удаляются
безвозвратно.** Для хранилища, в котором лежит единственная копия сырья,
это не мелкий шрифт: повторный обход судов стоит недели.

Старый вариант, если ключи держать в окружении, а не в файле:

```bash
export HARVESTER_S3_BUCKET=…  HARVESTER_S3_ENDPOINT_URL=…
export HARVESTER_S3_ACCESS_KEY=…  HARVESTER_S3_SECRET_KEY=…

python -m harvester archive --dry-run     # посмотреть, что поедет
python -m harvester archive               # сырьё
python -m harvester archive --model       # сырьё и веса
```

Ключи берутся только из окружения и в файлы настроек не попадают.

Выгрузка идёт **разницей**: сырьё адресуется содержимым (`sha256`), значит
лежащее в бакете не меняется и не перезаливается. Дело не в трафике —
у провайдера он бесплатный, — а во времени: сорок гигабайт мелких файлов
заливаются долго, и повторять это на каждый прогон нельзя.

Рядом с каждой страницей едет её `.json` с провенансом. Без него архив
превращается в мешок неопознанных страниц.

Веса именуются датой обучения (`captcha-model-2026-08-19.json`), чтобы
переобучение не затирало предыдущие.

## Порядок восстановления

Приоритет обратный привычному: **сырьё дороже базы**. База выводится
из сырья переразбором за часы, а сырьё заново — это недели обхода судов.

1. сырьё из `raw/`;
2. `alembic upgrade head`, справочники, переразбор;
3. веса из `model/` — либо переобучение на корпусе, полчаса.
