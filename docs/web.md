# Веб-интерфейс поиска

Страница поиска и read-only API над тем же `search.py`, что у CLI и MCP.
Макеты и разбор типовых систем — в холсте Design «Поиск по судебной
практике» (вариант B).

## Состояние на 11.10.2026

**Работает локально; на сервер не выложено.** Код — `src/harvester/web/`:
`create_app()` (FastAPI) и `index.html` (одна страница, ванильный JS,
без сборки). Тесты — `tests/test_web.py`.

| Адрес | Что |
| --- | --- |
| `/` | страница: главная → выдача с чтением акта → страница акта |
| `/api/search` | `q` (одна строка), `instance` (`all/kas/ap/vs/ks`), `sort`, `date_from`, `date_to`, `limit`, `offset` |
| `/api/suggest` | подсказки: норма из строки, номер дела по подстроке |
| `/api/act` | акт целиком по `ref` из выдачи и «Движение дела по инстанциям» |

## Как открыть

Сервис слушает только `127.0.0.1`, наружу его выводит туннель владельца.
Корпус несёт необезличенные ФИО, поэтому публикация в интернет — отдельное
решение (`docs/mcp.md`, то же рассуждение).

```bash
# на сервере (один раз; ставит владелец)
install -m 644 deploy/systemd/sudrf-web.service /etc/systemd/system/
.venv/bin/pip install -e '.[api]'
systemctl daemon-reload && systemctl enable --now sudrf-web

# на маке
ssh -N -L 8766:127.0.0.1:8766 root@157.22.194.96
open http://127.0.0.1:8766
```

Локально против своей базы: `HARVESTER_DATABASE_URL=… python -m uvicorn
--factory harvester.web:create_app --port 8766` (схема должна быть на
`head`: нужны таблицы ВС и КС).

## Что решено

* **Одна строка.** Нормы вырезаются из неё `norms.split_query`; номер
  дела узнаётся по виду (`NUMBER`); остальное — слова. Разобранное
  возвращается в ответе, и страница показывает его фишками.
* **Только чтение — свойство соединения** (`default_transaction_read_only`,
  `statement_timeout`), а не аккуратность кода. Те же две строки — в unit.
* **Охват назван в выдаче.** Для поиска по словам и нормам ответ несёт
  `texts_share` — долю актов корпуса с разобранным текстом, потолок
  полнотекста. Это не «полнота корпуса» и не доля среди найденных;
  `collected_share` наружу не отдаётся (roadmap: query-aware охват).
* **ВС и КС — над основной выдачей, по пять, только на первой странице.**
  Два источника под одним `offset` смешивать нельзя. «Только ВС» и
  «только КС» — фильтры инстанции, там страницы идут обычным порядком.
* **Защита от DNS-rebinding:** `Host` только `localhost` и `127.0.0.1`.

## Чего нет

* Пагинация — `offset`, не keyset: окно ранжирования (`RANK_WINDOW`) и
  так ограничивает глубину. Публичному API нужен курсор.
* Фильтры только по инстанции и порядку; суд, судья, даты — параметрами
  API есть (даты), в странице нет.
* Подсказки — норма и номер дела. Суды и фразы нечем подсказывать, пока
  нет словаря.
* Подсветка слов в акте — по основе слова без двух последних букв,
  подсказка глазу, а не доказательство совпадения.
* Нет «Суть» акта: резюме в корпусе не хранится.
